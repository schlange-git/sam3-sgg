# 多头对象分类拆分用于 SGG 的工程化实现说明

## 摘要

本文档给出在 `SAM3 + SpeaQ + Action Genome` 框架中落地“对象分类头拆分（Class Head Split）”的完整工程方案。核心思想是将单一对象分类头拆分为多个互斥职责头（`regular`、`small_shared`、`fine groups`、`bg`），并在对象侧先重组为统一类别空间 logits，再进入现有 relation / triplet 管线。该设计在不改 matcher、不改 relation head、不改 triplet 定义的前提下，为小目标与高混淆类别提供更高的判别自由度，并保持与既有训练框架兼容。

---

## 1. 问题定义与约束

### 1.1 背景

传统单头分类（single shared head）在场景图生成任务中往往对低频小目标类别不友好，原因包括：

1. 参数共享导致判别边界被高频类别主导；
2. 小目标类别与常规类别共享同一 logits 标度，难以稳定优化；
3. 细粒度高混淆类别组对单一线性头容量敏感。

### 1.2 工程约束

本实现严格遵循以下约束：

1. 不改 Hungarian matcher；
2. 不改 relation 分支结构；
3. 不改 triplet 构造定义；
4. 先在对象侧组装统一 `pred_logits`，再进入关系预测与评测；
5. 上采样仅用于分类前最后一步的 small/fine 分支；
6. 类别拆分由配置显式给定，不做自动聚类。

---

## 2. 方法

## 2.1 类别空间拆分

给定前景类别集合 `C={0,...,K-1}`，构造互斥划分：

- `C_regular`
- `C_small_shared`
- `C_fine^g, g=1..G`

并要求：

1. 两两不相交；
2. 并集覆盖 `C`；
3. 背景类别单独由 `bg head` 输出。

### 2.2 多头结构

在 `IterativeRelationTransformer` 中将对象分类由单头线性层扩展为：

1. `regular_head: R^D -> R^{|C_regular|}`
2. `small_shared_head: R^D -> R^{|C_small_shared|}`
3. `fine_head_g: R^D -> R^{|C_fine^g|}`
4. `bg_head: R^D -> R^1`

其中 `small_shared` 与 `fine_g` 可配置启用 2x bilinear 上采样路径。

### 2.3 统一 logits 组装

各分支先输出局部 logits，再写回全类别张量：

`logits_full ∈ R^{L×B×Q×(K+1)}`

并将未负责类别位置初始化为极小值（如 `-1e4`），最后填充背景列。  
这样可保持下游 `pred_logits` 接口不变。

### 2.4 多头温度校准

为缓解头间分布偏移，引入每头温度参数：

- `tau_regular`, `tau_small`, `tau_fine_g`

组装前执行 `logits / tau`（可配置开关）。

### 2.5 辅助损失

在 criterion 侧新增 split auxiliary losses：

- `loss_reg_aux`
- `loss_small_aux`
- `loss_fine_aux`

其监督来自 matcher 后 matched query，按 GT 类别映射到对应分支局部 label 空间进行 CE 计算，并在 subject/object 角色上做平均融合。

## 3. 实现细节

## 3.1 配置层

在 `configs/defaults.py` 新增：

- `MODEL.OBJ_SPLIT.ENABLED`
- `MODEL.OBJ_SPLIT.REGULAR_CLASSES`
- `MODEL.OBJ_SPLIT.SMALL_SHARED_CLASSES`
- `MODEL.OBJ_SPLIT.FINE_GROUPS`
- `MODEL.OBJ_SPLIT.FINE_GROUP_NAMES`
- `MODEL.OBJ_SPLIT.FINE_GROUPS_USE_UPSAMPLE`
- `MODEL.OBJ_SPLIT.SMALL_SHARED_USE_UPSAMPLE`
- `MODEL.OBJ_SPLIT.USE_TEMP_SCALING`
- `MODEL.OBJ_SPLIT.AUX_LOSS_WEIGHT_*`

并在 `configs/speaq_actiongenome_minimal.yaml` 增加对应配置块（默认关闭）。

## 3.2 启动校验

在 `modeling/meta_arch/detr.py` 增加 `validate_obj_split_config(cfg, num_classes)`，在模型构造早期执行，保障：

1. 类别 ID 合法；
2. 子集互斥；
3. 前景覆盖完整；
4. fine names / upsample 配置长度一致。

## 3.3 模型前向输出增强

在 `modeling/transformer/transformer.py` 中：

1. 新增 `SplitObjectClassifier`；
2. `IterativeRelationTransformer` 支持 split-head 输出；
3. 额外输出：
   - `obj_split_subject_head_source_idx`
   - `obj_split_object_head_source_idx`
   - `raw_split_logits_subject`
   - `raw_split_logits_object`

在 `modeling/transformer/detr.py` 中将上述字段透传到最终输出，并提供 aux 层版本。

## 3.4 损失函数增强

在 `modeling/transformer/criterion.py` 中新增：

1. split 配置解析；
2. `get_obj_split_aux_losses()`；
3. 在主层和 aux 层损失聚合中接入 split auxiliary loss。

## 3.5 评测分析增强

在 `evaluation/sg_evaluation.py` 中新增 triplet 级 head-source 统计：

- `subject_head_source_count`
- `object_head_source_count`
- `pair_head_source_count`

并写入评测结果字典，便于消融分析。

---

## 4. 复杂度与兼容性分析

### 4.1 计算复杂度

假设共享头复杂度为 `O(Q·D·K)`，多头拆分后复杂度近似：

`O(Q·D·(|C_regular| + |C_small| + Σ|C_fine^g| + 1))`

由于类别空间总和与原任务相同，理论主项不变；额外开销主要来自：

1. 多个线性层的参数常数项；
2. small/fine 分支上采样与适配操作；
3. 额外 auxiliary loss 计算。

### 4.2 训练稳定性

通过统一 logits 组装保持与原损失接口一致，降低系统性回归风险；温度校准可缓解头间分值不可比问题。  
split auxiliary loss 为可加权项，可从 0 逐步升高进行平滑迁移。

### 4.3 向后兼容

当 `MODEL.OBJ_SPLIT.ENABLED=False` 时，路径回退到原始单头分类行为，不影响现有训练脚本与 checkpoint 使用习惯。

---

## 5. 实验建议（对齐任务文档）

建议按以下顺序进行：

1. Baseline（单头）
2. Split only
3. Split + small 2x
4. Split + small 2x + fine heads
5. + temperature scaling

每阶段记录：

1. per-class recall；
2. `C_small_shared` 平均 recall；
3. 各 `C_fine^g` 平均 recall；
4. triplet R@K / mR@K；
5. head-source triplet 统计。

---

## 6. 结论

该实现将“分类头拆分”从概念方案转换为可训练、可评测、可消融的工程结构，重点保证：

1. 结构可控：配置驱动、启动即校验；
2. 逻辑闭环：对象侧统一 logits -> relation -> triplet；
3. 评测可解释：新增 head-source 统计；
4. 迁移成本低：默认关闭时保持原行为不变。

这使后续论文实验可以在统一框架下递进开展，并具备可重复的工程基础。
