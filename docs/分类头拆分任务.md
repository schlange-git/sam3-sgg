# 文件名：cursor_task_class_head_split_initial.md

# 任务目标
在当前 `SAM3 + SpeaQ + Action Genome` 框架上，实现一个初版的对象分类头拆分方案。该方案遵循以下硬约束：

1. `0/0` 表示当前评测标注集合里没有该类，不作为异常处理对象；
2. 不做像素统计，不做尺度分桶，不做自动聚类；
3. 只对人工认定的小目标类别做 2x 特征上采样；
4. 只对极少数“低分且高混淆”的类别组建立独立 fine head；
5. 常规类别头不再承担这些小目标类别的分类任务；
6. 不同分类头的输出必须在对象侧先整合成统一检测结果，再进入 relation / triplet 流程；
7. 初版优先保证结构清楚、改动可控、实验可复现。

---

# 一、方案定位

这不是一个完整的层级分类体系，也不是一个自动学习路由的大系统。初版只做三件事：

1. 把类别集合按人工规则拆成互斥的几部分；
2. 对其中“小目标部分”和“低分高混淆部分”分配独立分类头；
3. 在分类前的最后一步，对需要增强的小目标分支做简单 2x 上采样。

核心思想不是让所有头共同竞争所有类别，而是让不同头只负责自己那部分标签空间。这样可以避免常规类别和特殊类别共享完全相同的判别边界，也满足“常规类别头不再负责小目标类别”的要求。

---

# 二、必须先固定的前提规则

## 2.1 评测统计解释
本任务默认以下解释成立：

- `0/0`：该类在当前评测标注集合中没有被标注；
- `0/n`：该类存在 GT，但模型没有正确预测；
- 映射逻辑没有问题；
- 因此，本任务不再检查类别映射异常，也不围绕 `0/0` 做任何修复。

所有拆头决策只看两类信息：

- 有效评测类，也就是 `GT > 0` 的类别；
- 其中 recall 很低、而且具备明确小目标属性或明确混淆属性的类别。

---

## 2.2 类别划分原则
整个对象类别集合 `C` 必须被划分成互斥子集，不允许重叠。

划分结果包括四类：

### A. 常规类别集合 `C_regular`
这些类别由“常规类别头”负责。
它们不属于小目标增强集合，也不属于 fine head 集合。

### B. 小目标共享集合 `C_small_shared`
这些类别满足：
- 你人工认定它们属于常识性小目标；
- 它们不进入单独的 fine head；
- 它们统一交给“小目标共享头”负责。

### C. 细分类组集合 `C_fine_g`
每个 fine group 单独定义。
一个 fine group 只包含极少数类别，要求同时满足：
- 该组类别分数很低；
- 该组内部存在明显混淆；
- 该组内部尺度大体可接受，不做尺度明显冲突的硬绑定。

每个 fine group 由独立的 fine head 负责。

### D. 背景类 `C_bg`
单独由背景/空框分支负责。

注意：
- `C_regular`、`C_small_shared`、所有 `C_fine_g` 彼此互斥；
- 所有前景类必须被完整覆盖；
- 任何进入 `C_small_shared` 或 `C_fine_g` 的类别，必须从 `C_regular` 中移除；
- 常规类别头永远不输出这些类别的位置。

---

## 2.3 上采样使用原则
本任务只允许一种上采样方式：

- 对指定分支在进入分类头前的最后一级二维特征做 `2x bilinear interpolate`

不允许：
- 对输入图像上采样；
- 对 backbone 全图特征统一上采样；
- 对所有 query 一律上采样；
- 做 4x；
- 引入额外的尺度统计模块。

上采样触发条件只有两种：

1. 样本所属类别属于 `C_small_shared`；
2. 样本所属 fine group 被标记为“小目标组”。

---

# 三、模型结构重构

## 3.1 总体结构
对象检测分支由一个单头分类器改为四类模块：

1. 常规类别头 `regular_head`
2. 小目标共享头 `small_shared_head`
3. 若干个细分类组头 `fine_head_dict`
4. 背景头 `bg_head`

其中：
- `regular_head` 只负责 `C_regular`
- `small_shared_head` 只负责 `C_small_shared`
- `fine_head_dict[g]` 只负责 `C_fine_g`
- `bg_head` 只负责 no-object

最终不会再保留一个“全类别共享头”。分类任务被真正拆开，标签空间由不同头分别承担。

---

## 3.2 输入特征约定
设 object query 的最终分类前特征为 `F_obj`。

需要额外暴露两种版本：

- `F_regular`：直接送常规类别头；
- `F_small`：送小目标共享头或小目标细分类组头；
- `F_fine_g`：送第 g 个细分类组头。

初版要求：

- `F_regular` 可以直接使用当前对象分类前的 query 特征；
- `F_small` 和 `F_fine_g` 必须在送入头之前保留二维结构，才能执行 2x 上采样；
- 如果当前代码里分类前只有一维 token 特征，则必须在分类前新增一个轻量二维特征适配层，把分类前特征转为小尺寸二维特征图后再上采样。

二维适配层只服务于需要上采样的头，不影响常规类别头。

---

## 3.3 二维适配层
如果当前分类路径没有现成二维局部特征，则新增：

- `small_feat_adapter`
- `fine_feat_adapter_dict`

作用：
- 把分类前的一维 query feature 投影成一个小尺寸二维 feature map；
- 推荐尺寸固定为 `h x w`；
- 然后执行 `2x` 上采样；
- 再通过轻量卷积或池化得到分类输入。

初版要求：
- 适配层必须轻量；
- 只在小目标头和被标记为小目标的 fine head 上启用；
- 常规类别头不经过该适配层。

---

## 3.4 分类输出组装方式
各头不直接输出完整类别空间，只输出自己负责的子集 logits：

- `regular_head(F_regular) -> logits_regular`，维度为 `|C_regular|`
- `small_shared_head(upsample(F_small)) -> logits_small`，维度为 `|C_small_shared|`
- `fine_head_g(F_fine_g or upsample(F_fine_g)) -> logits_fine_g`，维度为 `|C_fine_g|`
- `bg_head(F_obj) -> logit_bg`，维度为 `1`

然后在对象侧组装统一 logits：

- 新建 `logits_full ∈ R^{B × Nq × (C+1)}`
- 先全部填充为极小值
- 把 `regular_head` 输出写入 `C_regular` 对应列
- 把 `small_shared_head` 输出写入 `C_small_shared` 对应列
- 把各 `fine_head_g` 输出写入 `C_fine_g` 对应列
- 把背景头输出写入最后一个 `no-object` 列

这样得到的 `logits_full` 才是最终的对象分类输出，也就是新的 `pred_logits`。

这个组装方式有三个优点：

1. 不需要额外路由网络；
2. 不会出现常规类别头和小目标头同时负责同一类别；
3. 现有 `SetCriterion` 和后处理逻辑可以继续使用统一的 `pred_logits` 接口。

---

## 3.5 分数校准
不同分类头输出的 logit 分布可能尺度不同。为了防止某个头分数偏大导致统一输出后失衡，需要给每个头增加一个可学习温度参数或偏置参数：

- `tau_regular`
- `tau_small`
- `tau_fine_g`

组装前先做校准：

- `logits_regular = logits_regular / tau_regular`
- `logits_small = logits_small / tau_small`
- `logits_fine_g = logits_fine_g / tau_fine_g`

初版只做温度缩放，不做额外复杂校准网络。

# 五、训练逻辑

## 5.1 匹配方式

保持现有 Hungarian matcher 不变。

也就是说：

* 仍然先做 object-level matching；
* 匹配结果仍然是 query 与 GT object 的一一对应；
* 不对 matcher 做分类头级别改造。

这样做的原因是：初版目标是验证分类头拆分本身是否有效，不同时引入匹配策略变化，避免变量过多。SpeaQ 的 specialization 思想强调“通过专门化获得更清晰训练信号”，你的初版正是把这一思想从 relation 侧迁移到 object 侧，但不同时改 assignment。 

---

## 5.2 对象分类损失

对象分类主损失仍然对统一后的 `logits_full` 计算交叉熵。

也就是：

* `SetCriterion.loss_labels` 的接口不改；
* 目标标签仍然是原始 AG 类别索引；
* no-object 仍然是最后一类；
* 只是 `pred_logits` 不再来自一个线性层，而是来自多个头拼接后的统一输出。

这样能保证：

* 现有损失接口不变；
* 当前训练管线改动最小；
* 不需要为不同头分别重写完整分类损失。

---

## 5.3 头部辅助损失

除了统一后的主 CE，再为每个头增加一个局部辅助 CE。

### 常规类别头辅助损失

仅在 GT 类别属于 `C_regular` 的 matched query 上计算。

### 小目标共享头辅助损失

仅在 GT 类别属于 `C_small_shared` 的 matched query 上计算。

### 细分类组头辅助损失

仅在 GT 类别属于 `C_fine_g` 的 matched query 上计算。

总损失写为：

`L_obj = L_full + λ_reg * L_reg_aux + λ_small * L_small_aux + Σ_g λ_fine_g * L_fine_aux_g`

建议初始权重：

* `λ_reg = 0.2`
* `λ_small = 0.5`
* `λ_fine_g = 0.5`

如果训练波动较大：

* 把所有辅助权重先降到 `0.2`

这样做的意义是：

* 统一输出负责最终类别竞争；
* 局部辅助损失保证每个头在自己的标签子空间上学得更稳。

---

## 5.4 回归损失

边框回归仍沿用当前 object 分支的 `loss_bbox + loss_giou`，不拆分，不分头。

也就是：

* 分类头拆了；
* box 头先不拆；
* 所有 query 仍共用当前 box regression 分支。

初版不做 head-specific box head，避免结构膨胀。

---

# 六、推理逻辑

## 6.1 对象结果生成

推理时按训练同样的方式生成：

* `logits_full`
* `pred_boxes`

然后对 `logits_full` 做 softmax，得到统一类别概率。

注意：

* 常规类别来自 `regular_head`
* 小目标共享类别来自 `small_shared_head`
* 细分类组类别来自对应 `fine_head`
* no-object 来自 `bg_head`

对象侧后处理只认统一后的 `pred_logits`，不再关心具体头来源。

---

## 6.2 每个 query 的头来源记录

为了后续分析，推理阶段额外输出一个 `head_source_idx`：

* 若最终类别属于 `C_regular`，记为 regular
* 若最终类别属于 `C_small_shared`，记为 small_shared
* 若最终类别属于某个 `C_fine_g`，记为 fine_g

这个字段只用于日志和误差分析，不进入评测。

---

## 6.3 头间分数不可比问题

如果发现：

* 某一头输出分数系统性过高；
* 某一头输出几乎从不被选中；

优先调的不是损失，而是温度参数和辅助损失权重。

初版不要引入更复杂的后处理规则。

---

# 七、triplet 任务整合方案

## 7.1 核心原则

不同分类头的检测结果不能分别走 relation，再在最后硬拼接 triplet。

正确做法是：

1. 先在对象侧整合成唯一的对象检测结果；
2. relation 分支继续基于这组统一的对象 query 编号工作；
3. triplet 构造阶段继续使用当前 `(rel_pair_idx, relation_logits, pred_logits, pred_boxes)` 逻辑。

原因很明确：
当前代码中 triplet 的 subject/object 来自对象检测结果，relation 则通过 `rel_pair_idx` 绑定到对象 query，再去重后计算 triplet 匹配。也就是说，relation / triplet 管线依赖的是“统一对象结果”，不是“多个对象头各自结果”。

---

## 7.2 relation 分支是否要拆

初版不拆 relation 头，不改 relation query，不改 relation matcher。

保持：

* `relation_logits` 的产生方式不变；
* `rel_pair_idx` 的产生方式不变；
* relation loss 不变。

这样做的原因：

* 你当前要验证的是对象分类拆头对 SGG 是否有帮助；
* relation 侧如果同时改动，就无法判断收益来自哪里。

---

## 7.3 triplet 构造

triplet 构造时按现有流程走：

1. 从统一的 `pred_logits` 中得到每个对象 query 的类别与分数；
2. 从统一的 `pred_boxes` 中得到每个对象框；
3. relation 分支给出 `relation_logits` 与 `rel_pair_idx`；
4. 通过 `rel_pair_idx` 找到 subject query 和 object query；
5. 组合成 `(sub_label, pred_label, obj_label)`；
6. 继续使用当前去重逻辑与 `_compute_pred_matches`。

不新建第二套 triplet 生成逻辑。

---

## 7.4 triplet 分数

triplet 分数继续定义为：

* `score_triplet = score_sub * score_pred * score_obj`

其中：

* `score_sub` 和 `score_obj` 来自统一对象分类结果；
* `score_pred` 来自 relation 分支。

由于对象类别来自不同头，需要记录并分析不同头来源对 triplet 分数的影响，但初版不改 triplet 打分公式。

---

## 7.5 triplet 分析项

新增三类统计：

### A. 按头来源统计 triplet recall

区分：

* regular-head 产出的对象参与的 triplet
* small-head 产出的对象参与的 triplet
* fine-head 产出的对象参与的 triplet

### B. 按对象角色统计

区分：

* 该对象作为 subject 时的收益
* 该对象作为 object 时的收益

### C. 按类别子集统计

重点观察：

* `C_small_shared` 上的 triplet 变化
* `C_fine_g` 上的 triplet 变化

这些统计不改变评测协议，只用于 ablation 分析。
